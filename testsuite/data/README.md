# libmedio test data

This directory holds the data files used to validate libmedio. The tests
of the `testsuite/` directory pick up all datasets found here
automatically, so adding a dataset requires no changes to the test code.

## Layout

```
testsuite/data/
├── README.md
├── tools/
│   └── make_expected.py        # generates the expected values of a dataset
├── ecat7/                      # format of the original data file
│   ├── <dataset>/              # one directory per dataset (acquisition)
│   │   ├── dataset.json        # description and expected values
│   │   ├── <data file(s)>      # original file, e.g. image.v
│   │   └── reference/          # optional: the same acquisition in other
│   │       └── ...             #   formats or written by other tools
│   └── ...
├── ecat6/
├── nifti/
├── philips/
└── micropet/
```

- The first level is the format of the original data file, the second
  level one directory per dataset with a short, descriptive name using
  lower case letters, digits and dashes (e.g. `phantom-static`,
  `brain-dynamic-28frames`, `sinogram-3d`).
- `reference/` contains the same acquisition in other formats (e.g. a
  NIfTI file converted from the original DICOM data with dcm2niix). These
  files are used to validate the format conversions of libmedio. Datasets
  without reference files are fine, e.g. for tests of a single format.

## dataset.json

Every dataset directory contains a `dataset.json`:

```json
{
  "description": "NEMA IEC body phantom, static, 10 min",
  "source": {
    "scanner": "ECAT EXACT HR+",
    "reconstruction": "OSEM 4 iterations/16 subsets, 5 mm Gauss",
    "units": "Bq/ml",
    "notes": "head of the phantom at high z"
  },
  "file": "image.v",
  "references": [
    {
      "file": "reference/dcm2niix.nii.gz",
      "tool": "dcm2niix v1.0.20250505 -z y",
      "same_reconstruction": true,
      "notes": "converted from the DICOM export of the same reconstruction"
    }
  ],
  "landmarks": [
    {
      "name": "center of the 37 mm sphere",
      "voxel": [64, 80, 31],
      "world_mm": [0.0, 32.9, -12.4]
    }
  ],
  "expected": { "...": "generated by tools/make_expected.py" }
}
```

| Key           | Required | Content                                                                 |
|---------------|----------|-------------------------------------------------------------------------|
| `description` | yes      | what the dataset contains                                              |
| `source`      | no       | scanner, reconstruction, units and other free-form information          |
| `file`        | yes      | data file of the dataset, relative to the dataset directory             |
| `references`  | no       | the same acquisition written by other tools, incl. tool name and options |
| `landmarks`   | no       | points with known positions (voxel indices of `file`, world coordinates in mm of the references) |
| `expected`    | yes      | expected header and voxel values, see below                             |

### Expected values

The `expected` block is **generated** with `tools/make_expected.py`, which
reads the data file with [nibabel](https://nipy.org/nibabel) as an
independent implementation, so libmedio is not validated against itself:

```bash
pip install nibabel numpy
python3 testsuite/data/tools/make_expected.py testsuite/data/ecat7/<dataset>
```

The script creates `dataset.json` if it does not exist yet and only
replaces its `expected` block otherwise, so the manually written keys are
kept. Do not edit the `expected` block by hand; values which cannot be
generated (e.g. for file types the script does not support) may be added
manually, the tests only check the keys that are present.

For ECAT7 image files `expected` contains the main header values
(`file_type`, `num_frames`, `num_planes`, `calibration_factor`,
`data_units`) and for every matrix its index (`frame`, `plane`, `gate`,
`bed`, `data`), the sub header values (`data_type`, `dims`,
`pixel_size_cm`, `scale_factor`, `frame_start_time_ms`,
`frame_duration_ms`) and statistics of the stored (unscaled) voxel values
(`raw_min`, `raw_max`, `raw_sum`).

## Adding a dataset

1. Create `testsuite/data/<format>/<dataset>/` and copy the data file and,
   if available, the reference files into it.
2. Write `dataset.json` with at least `description` and `file` (or let
   `make_expected.py` create it and fill in `description` afterwards).
3. Run `tools/make_expected.py` on the dataset directory. It also checks
   that the files listed in `references` exist.
4. Build and run the tests (`ctest`), then commit the dataset directory.

## Placeholders

A dataset directory containing a `PLACEHOLDER.md` waits for its data: it
describes which files are expected and is skipped by the tests as long as
the data file listed in its `dataset.json` is missing. Once the data file
was added, `tools/make_expected.py` generates the expected values and
removes the `PLACEHOLDER.md` files. A dataset with data file and remaining
`PLACEHOLDER.md` is reported as error by the tests.

## Rules

- **Size:** keep datasets small; a phantom or a small matrix with a few
  frames is sufficient for validation. Aim for a few MB per file; GitHub
  rejects files larger than 100 MB. Git LFS is intentionally not used.
- **Anonymization:** the repository is public. Data files must not contain
  personal data: anonymize patient name, ID, birth date and similar fields
  before adding a dataset.
- **License:** only add data that may be redistributed under the license
  of this repository.

## Larger local datasets

The location of the test data can be changed when configuring the build:

```bash
cmake -S . -B build -DMEDIO_TEST_DATA_DIR=/path/to/testdata
```

The directory has to follow the layout described above. This allows
running the tests on larger datasets which are not part of the repository.
Tests skip formats for which no dataset is found.
